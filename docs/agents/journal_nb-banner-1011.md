## 1 — The premise in the brief was wrong, and it changed the method

The brief said *"Notebooks 10 and 11 are **NOT** generated by `src/nbgen/` … VERIFY THIS"*.

**Verified: they ARE generated.** `src/nbgen/make_nb10.py` and `src/nbgen/make_nb11.py` both exist,
and both are live — regenerating each into a scratch directory reproduces the committed notebook's
cell sources **byte-for-byte** (11/11 and 23/23 cells identical before any edit). CLAUDE.md's line
*"Notebooks 10/11 are generated by `src/nbgen/make_nb*.py`"* is correct as written.

So the generator is the source of truth and had to be edited. But the brief's next clause —
*"regenerate, and re-execute"* — **was not followed**, deliberately, and this is the one judgement
call in the run:

> **Re-executing notebook 11 rewrites the adopted forcing.** Its export cell (cell 22 after the
> edit) writes `forcing_minibacia_precip_v2.csv`, `forcing_minibacia_provenance_v2.csv` and
> `forcing_minibacia_pet_v2.csv` into `data/processed/`. That is the **v2 forcing the frozen H2E
> configuration was fitted on** (CLAUDE.md Phase B; `docs/00_INDEX.md` "Forcing versions"). A
> markdown-only documentation repair must not put a byte of it at risk, and the brief's own hard
> constraint — *"you must not leave either notebook less executed than you found it"* — points the
> same way. Notebook 10 additionally re-reads the CHIRPS netCDF stack and re-runs a 294-gauge LOOCV
> on ~2 GB of free RAM.

**What was done instead**, which reaches the same end state with none of the risk:

1. the banner and annotation text was added to **the generators** (so a future `make_nb1x.py` run
   reproduces them);
2. the change was mirrored into the executed `.ipynb` by a script that rebuilds the cell list from
   the freshly generated notebook while **carrying every code cell's `execution_count` and
   `outputs` over verbatim**. The script *asserts* the safety contract before writing: same number
   of code cells, and every code-cell source byte-identical. It refuses to run otherwise.
3. Post-check: regenerating from the edited generators reproduces the edited notebooks
   byte-for-byte again (12/12 and 24/24 cells, `IDENTICAL SOURCES`). **Generator and notebook are
   in sync; no re-execution is owed.**

No code cell was touched. No file under `data/` was touched. No git command was run.

   `grep` finds no "UNKNOWN" in `docs/33`, `docs/18` or `docs/agents/journal_chirps-refit.md`. What

   **wrong** (`docs/33` §1, `docs/18` §15.5), and *"no route to a passing volume gate exists inside
   the merge code"* — with one **untested** upstream hypothesis surviving (the 139 residual
   rain-selective stations, whose missing days are not in the record at all). This is consistent
   with A1's independent wording in `docs/00_INDEX.md`: *"the cause of the volume failure is not
   settled … Do not write that the fix is known."* **Nothing in either notebook claims a known
   fix, and nothing promises a v3.**
2. **Re-executing either notebook.** Reasoned in §1. The change is markdown-only, so re-execution
   would alter no result while risking the adopted v2 forcing files and the executed state.
   Generator/notebook parity was proven by regeneration instead.
3. **Rewriting any original sentence.** House style from `docs/46` (its READ OUT block and §1.0's
   *"SUPERSEDED AND NOT QUOTABLE"* pattern) is append-and-annotate. Every stale passage above is
   still legible in full.
4. **`docs/30` §1's own stale clause.** It says the CHIRPS merge *"failed only its volume gate,
   **with the fix identified**"*. After the H-CHIRPS read-out that clause is wrong — the identified
   fix was the no-op. **Not mine to edit** (`docs/30` is outside my file ownership). Raised here for
   whoever owns it; `docs/30` §5 item 1's *"If not, the negative result closes the question"* branch
   is the one that actually fired.
5. **`docs/33` §1's mis-firing pointer.** Its resolution note reads *"[resolved 2026-08-10 — see

   independently.
6. **CLAUDE.md's *"Notebooks 10/11 are generated by `src/nbgen/make_nb*.py`"*.** Correct as written
   — verified by byte-for-byte regeneration. No change owed.
7. **nb10's §5 header *"### Gauges or CHIRPS (sections 3-4): neither alone"* and the framing
